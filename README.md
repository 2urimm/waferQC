# waferQC

저해상도(8×8, 64칸) 웨이퍼 결함 스크리닝 플랫폼 프로토타입 — **공정 엔지니어용 원인 추적 UI**.

분류 결과를 라벨로 끝내지 않고 "그래서 어느 공정부터 열어봐야 하나"까지 연결하는 것이 이
프로젝트에서 UI가 맡은 몫이다. 분류기를 의사결정 지원 도구로 확장하는 지점이 여기다.

> **개념 검증 프로토타입이다.** 실제 fab 데이터로 검증된 적 없고 상용 장비와 비교한 적도 없다.
> 화면 곳곳에 이 범위를 명시해 두었고, 그 문구를 지우지 말 것.

## 두 층으로 된 판정

모델은 **9클래스**(Center / Donut / Edge-Loc / Edge-Ring / Loc / Random / Scratch / Near-full / None)를
출력한다. UI는 그걸 그대로 띄우지 않고 두 층으로 보여준다.

1. **계통** — 9클래스를 6개 계통(정상 / 중심계 / 외곽계 / 국부계 / 산발계 / 전면계)으로 묶은 확률.
   8×8에서는 인접 클래스끼리 확률이 새기 때문에 계통 단위가 훨씬 안정적이다.
2. **9클래스 확률** — 모델 원본. 각 후보에 **어느 피처가 그 순위를 만들었는지** 실제 수치를 인용한 근거를 붙인다.

각 클래스는 정확히 한 계통에만 속하므로 계통 확률은 소속 클래스 확률의 합이고, 합이 보존된다.

### 못 하는 것을 못 한다고 말한다

8×8에서 구조적으로 갈리지 않는 쌍(Center↔Donut, Donut↔Edge-Ring, Loc↔Scratch, Edge-Loc↔Edge-Ring)은
판정 화면의 **"이 판정의 한계"**에 근거와 함께 그대로 노출된다. 대신 그 둘을 가르는 데 쓰이는
연속 수치(군집 이방성, 외곽 각도 분산)를 판정 근거로 같이 내보내 엔지니어가 직접 읽게 한다.

### 사람 검토 여부를 판정보다 먼저

"이 판정을 그대로 믿고 공정을 열어도 되는가"가 클래스 이름보다 먼저 답해야 할 질문이다.
모델의 검토 정책(1순위 확률 부족 / 항상 검토 클래스 / 불량 밀도 극단 등)에 걸리면
판정 카드 **위에** 사유와 함께 경고가 뜬다.

## 원인 추적이 실제로 하는 일

`src/domain/causes.ts`에 결함 패턴 × 요인 유형(정적 / 경시 / 방향성 / R2R) 매트릭스가 들어 있다.
`src/domain/plan.ts`가 이걸 이번 측정에 맞춰 공정별로 재배열한다. 순위는 세 가지를 같이 본다.

1. 세부 패턴 후보의 확률 — 유력한 패턴의 원인 공정일수록 위로
2. 요인 축의 폭 — 여러 축에서 지목될수록 유력
3. **이번 측정의 피처가 실제로 그 원인을 지지하는가**

3번이 이 UI가 조회표 이상인 지점이다. 예를 들어 원본 표의 *"6시 하단 노치 — Gate door 파티클"* 항목은,
측정된 결함 방위가 실제로 6시면 **"✔ 이번 측정이 지지 — 사실상 확정에 가깝다"**로 1순위에 올라오고,
방위가 3시면 **"△ 측정과 불일치"**로 순위가 내려간다. 같은 패턴이라도 측정에 따라 순서가 바뀐다.

또 하나의 구분: **경시 변화(aging)와 R2R 원인은 웨이퍼 한 장으로 확인할 수 없다.** 이력 대조가
필요한 항목은 `⏱ 이력 대조 필요`로 따로 표시해 "지금 볼 것"과 갈라 둔다.

지식베이스에 아직 원인이 없는 패턴·공정은 숨기지 않고 드러낸다 — 안 보이는 것과 "배제되었다"는 건 다르다.

## 하드웨어 모사

저장(74HC595)과 판독(CD4067)이 물리적으로 분리되어 있다는 게 이 프로젝트의 전제다.

- **74HC595** — 패턴을 8비트씩 밀어 넣고 한 번에 래치. 쓰기 시간은 셀 수에 거의 비례하지 않는다.
- **CD4067** — S0~S3로 한 번에 한 채널만 COMMON에 연결. 판독은 원리적으로 셀 개수에 비례한다.

이 비대칭이 `장비` 탭의 **해상도–측정시간 트레이드오프** 표다. 8×8은 프레임당 약 16 ms에 CD4067 4개.
같은 방식으로 52×52까지 가면 CD4067이 169개 필요하고 프레임은 수십 배가 된다. 저해상도 선택은
성능 타협이 아니라 "빠른 1차 스크리닝"이라는 목적에 맞춘 설계라는 걸 숫자로 보여주는 자리다.

원형 웨이퍼를 정사각 8×8 격자에 얹으면 네 모서리 12칸이 웨이퍼 밖이라 **유효 셀은 52칸**이다.
그 12칸은 모델 입력에서 `0`(웨이퍼 밖)이고, 불량 비율 계산의 분모에서도 빠진다.

## 판정 규칙을 고칠 때

`npm run verify`가 프리셋 9종의 계통·1순위 클래스를 회귀 기준선과 대조한다.
기준선이 깨지면 **고친 게 맞는지 기준선이 틀렸는지를 먼저 판단하고** 둘 중 하나를 고칠 것.

이 하네스가 실제로 잡아낸 것들:

- 대각 스크래치가 4-연결로 5개 군집으로 쪼개지던 문제 → 8-연결로 교체
- 8×8에서 외곽 링만으로 밀도 임계를 넘어 Edge-Ring이 Near-full로 오분류되던 문제
  → 전면의 서명은 밀도가 아니라 "최내측까지 찼는가"
- **링의 평균 반경은 정의상 중간값**이라 무게중심으로는 Donut을 절대 못 잡던 문제
  → 반경 프로파일의 형상(한 구간이 꽉 참 + 최내측 빔 + 중심을 둘러쌈)으로 판별
- 외곽 링에 붙은 군집이 격자 기하 때문에 저절로 직선이 되어 전부 Scratch로 읽히던 문제
