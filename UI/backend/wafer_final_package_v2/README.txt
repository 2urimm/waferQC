========================================================================
8×8 Wafer Map 최종 추론 패키지
========================================================================

이 폴더는 기존 ConvNeXt_CNN.ipynb의 최종 하드웨어 추론 경로만 정리한 버전입니다.

최종 경로는 다음과 같습니다.

8×8 hardware map → V2 9-class 최종 판정 → V3 보조 검토 → ACCEPT/REVIEW → Scratch/Loc/Edge-Loc 4방향 판정

현재 최종 출력 함수가 사용하는 모델은 V2 + V3입니다. V5 실험 모델은 이 실시간 최종 추론 경로에 포함하지 않았습니다.

9. 방향 좌표 기준
------------------------------------------------------------------------

소프트웨어 기준:

row 0 = 위
col 0 = 왼쪽

┌──────────┬──────────┐
│ 왼쪽 위  │ 오른쪽 위 │
├──────────┼──────────┤
│ 왼쪽 아래│ 오른쪽 아래│
└──────────┴──────────┘

실제 하드웨어 배선 순서가 좌우/상하 반전되어 있으면 방향 출력도 반대로 나옵니다. 최종 조립 후 한 모서리에만 defect를 넣어 좌표 방향을 1회 검증하세요.


------------------------------------------------------------------------
9-1. 결함 방향성 판정 기준
------------------------------------------------------------------------

방향 판정은 Scratch, Loc, Edge-Loc으로 분류된 경우에만 적용합니다.

8×8 wafer map을 4개의 4×4 영역으로 나눈 뒤, 각 영역의 defect die(값 2) 개수를 계산합니다.

방향성 판정 기준:

가장 많은 영역의 defect 개수 - 나머지 3개 영역 defect 개수의 평균 >= 2

즉, 특정 영역의 결함 개수가 나머지 세 영역의 평균보다 2개 이상 많을 때만 해당 방향의 결함으로 판단합니다.

예시)

왼쪽 위     : 8
오른쪽 위   : 5
왼쪽 아래   : 4
오른쪽 아래 : 5

나머지 3개 평균 = (5 + 4 + 5) / 3 = 4.67
방향성 차이 = 8 - 4.67 = 3.33

3.33 >= 2 이므로 → 왼쪽 위 방향성 결함으로 판정합니다.

반대로,

왼쪽 위     : 6
오른쪽 위   : 5
왼쪽 아래   : 5
오른쪽 아래 : 5

나머지 3개 평균 = 5
방향성 차이 = 6 - 5 = 1

1 < 2 이므로 → 방향성 불명확으로 처리합니다.

또한 가장 많은 영역이 2개 이상으로 공동 1등인 경우에는 한 방향을 강제로 선택하지 않고 방향성 불명확으로 처리합니다.

이전에는 '가장 많은 영역 - 두 번째로 많은 영역 >= N' 방식도 검토했으나,
N=2에서 전체 방향성 판정 비율이 24.19%로 크게 감소하여 너무 많은 샘플이 방향성 불명확으로 처리되었습니다.

최종적으로는 '가장 많은 영역 - 나머지 3개 영역 평균 >= N' 방식을 사용하며,
Validation 데이터 비교 결과 N=2를 최종 기준으로 설정했습니다.

N=2 기준 방향성 판정 비율:
• 전체: 50.21%
• Scratch: 64.04%
• Loc: 59.06%
• Edge-Loc: 40.76%

주의:
위 비율은 방향 판정 정확도가 아니라, 해당 기준을 적용했을 때 방향성이 있다고 판정되는 샘플의 비율입니다.

최종 출력 예:

Failure Type      : Scratch
Direction         : 왼쪽 위

또는 방향성이 충분하지 않은 경우:

Failure Type      : Scratch
Direction         : 방향성 불명확


------------------------------------------------------------------------
10. 현재 고정 정책
------------------------------------------------------------------------

현재 노트북에서 실제 생성된 최종 설정을 정리해 config.json에 고정했습니다.

• V3 binary threshold fallback: 0.68
• None review threshold: 0.49
• high defect cell threshold: 50
• Random / Near-full: 구조적 모호성으로 강제 REVIEW
• 클래스별 V2 threshold:
• Center 1.01
• Donut 1.01
• Edge-Loc 1.01
• Edge-Ring 0.30
• Loc 0.74
• Random 1.01
• Scratch 1.01
• Near-full 1.01
• None 0.30

실제 V3 binary threshold는 .pt 체크포인트 안의 binary_threshold 값을 우선 사용합니다.
